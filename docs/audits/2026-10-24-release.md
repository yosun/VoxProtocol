# VOX integrated audit release candidate — 2026-10-24

This candidate combines the audited account, character conversation, direct
messaging, checkout, and NFT features in one pull request to `main`. It includes
the current default branch's paid-order recovery and treasury-liability
protections. Production has not been changed by this audit.

## Correctness and security fixes

- Authorize private message attachments against durable per-uploader grants;
  knowing an asset hash does not grant access to another conversation's bytes.
- Page message history with conversation-bound cursors and deterministic ordering.
  Polling bridges multiple new pages, and responses from an earlier visit cannot
  overwrite the current conversation's history or cursor. Sender/client-message
  idempotency is reserved transactionally, with indexed legacy lookup.
- Block private-address link previews, including mapped IPv6, DNS rebinding, and
  unsafe redirects. Pin the validated DNS answer for the actual connection.
- Preserve the exact accepted payer, quote, payment intent, transfer signature,
  finalized transfer time, and replay reservation during payment recovery. An
  expired provider quote cannot trigger an unapproved new render. Late or
  ambiguous transfers remain captured for review, with the existing exact
  operator-controlled refund process.
- Retry a provider submission only after a complete, typed
  `COMMISSION_NOT_FOUND` response and only while the pinned request remains
  eligible. Reuse the original signed body, ID, idempotency key, and timestamps;
  lease retries and retain captured funds after ambiguous responses.
- Retain strict network-qualified settlement destinations. Allocations held in
  the treasury remain ledger liabilities, rather than completed external payouts.
- Correct Solana NFT metadata bytes and authority ordering; require finalized
  failure before a replacement attempt. Page NFT jobs past blocked records and
  recover expired signing leases. Preserve weighted commission queue fairness.
- Support real browser voice MIME types, preview-local livestream links,
  historical account NFT claims, and Base Sepolia wallet configuration.
- Save checkout checkpoints per commission/source post, retain pending signatures
  across navigation, and reverify submitted payments without a second wallet send.
  Persist the exact NFT/public-credit consent before acceptance so a lost response
  cannot reset the accepted choice. NFT publication stays separately optional.
- Upgrade vulnerable dependencies and replace the legacy native bigint buffer
  implementation with the reviewed pure-JavaScript implementation. Compatibility
  tests exercise protocol fixtures, schema limits, Solana codecs, Google clients,
  and single/batch web3 RPC.

## Release prerequisites and limits

The read-only production index plan found **8 missing composite indexes**: NFT
processing, four character-conversation queries, pending audience requests, and
two message-history/idempotency queries. No indexes were created during the audit.

The protected workflow provisions only missing manifest definitions and waits for
READY. Every API/reconciliation release checks readiness, even when the manifest
is unchanged. Provisioning uses a separate reviewed
`VOX_GCP_INDEX_SERVICE_ACCOUNT`; that variable was not configured at the audit
check. The application deploy identity retains its existing limited permissions.
See `infrastructure/gcp/README.md` for the identity and index release procedure.
Temporary index credentials are removed before the application build, and all
generated action credentials are excluded from source/build contexts.

One combined pull request must pass its required checks and human review. Any
release retains the `production-sensitive` owner gate. This audit did not merge,
deploy, change IAM or secrets, or initiate a Mainnet payment, payout, refund, or
paid provider render. The complete live payment → generation → settlement/refund
path still requires a separately authorized rehearsal; mocked tests do not prove
that live path has passed. Follow `docs/realize-staging-status.md` and
`docs/realize-mainnet-refund-operations.md` for those boundaries.
